01  最终代码

这是你今天交出来的版本。第 16 行那三个反引号改掉之后，块数才从 232 掉到 137。

def chunk_by_heading(path, text):
    chunks = []
    cur_title = "(开头)"
    cur_text = ""
    in_code = False                       # 文件开头站在代码块外面

    for line in text.splitlines():
        if line.strip().startswith("```"):   # 碰到围栏
            in_code = not in_code             # 取反：进 / 出
            continue                        # 围栏行本身不参与切块

        if line.startswith("## ") and not in_code:
            if cur_text:                     # ① 先结算
                chunks.append((path, cur_title, cur_text))
            cur_title = line                 # ② 再换标题
            cur_text = ""                    # ③ 最后清空
        else:
            cur_text += line + "\n"

    if cur_text:                             # 循环外兜底：最后一块等不到下一个标题
        chunks.append((path, cur_title, cur_text))
    return chunks

02  它其实是个状态机

只有两个状态变量，每行只有两种输入。四种组合，只有一种会触发「结算」：

这一行cur_text 有内容cur_text 为空
是 ## 结算旧块 → 换标题不结算 → 换标题
不是继续追加继续追加（空串追加无害）

「cur_text 为空」那种情况就是空块的来源：文件一上来就是 ## 1.1，或者两个标题挨着写、中间没正文。所以 if cur_text: 这行不能删——删了不报错，但会凭空多出若干空块，之后送进 embedding 就是纯噪音。

结构性认知

所有「边读边攒、遇到边界才交出」的代码，都是同一个形状：循环里结算 + 循环外兜底。日志切分、流式解析、按分隔符拆包，全是它。

03  为什么必须两处 append

因为「结算」这个动作，是被下一个标题的到来触发的。而最后一块永远等不到下一个标题——它在文件末尾。

▸行 0–10   攒了 452 字，标题是 (开头)，因为首行是 # 第一章 不是 ##
▸行 11   命中 ## 1.1 → 把 452 字交出去，标题记为 (开头)
▸行 12–…   开始攒 1.1 的正文
▸文件结束   这块还攥在手里 → 循环外补一次 append 才交得出去

04  今天踩的两个坑，是同一个形状

坑以为的实际的为什么难查
空块append 出去的是正文cur_text 是空字符串不报错，块数只多几个
围栏匹配到了 ```写成 ~~~，命中 0 行不报错，数字完全不变

「改了之后行为没变化」，第一反应应该是「我改的那行真的被执行到了吗」，而不是「这段逻辑没用」。

验证它其实只要一行：语料里反引号围栏有 1204 行，波浪号围栏 0 行。跑一次计数就知道自己在匹配什么。

05  面试怎么讲这段

「我做过一个 markdown 切块器。最初按二级标题切，切出 232 个块。后来发现块数虚高——用 grep 一查，有 95 个「标题」其实是 Python 模板字符串里的 ## 评估概览，它们顶格写在代码块内部，被误判成了章节。

修法是维护一个代码块开关：遇到围栏就取反，只有不在代码块里的 ## 才算真标题。修完降到 137 块，正好等于 232 减 95。

过程中还踩到两个静默失败：一个是空块没过滤，一个是围栏字符打成了 ~~~ 导致一次都没命中——两个都不报错。所以后来我加了断言，比较修改前后的块数差是否符合预期。」

06  明天从哪接着来

看最后一个数字：平均每块 6013 字，137 块里有 66 个超过 4000 字，最长的 23796 字。

embedding 模型只吃 512 个 token（中文约 400–700 字）。也就是说这些块送进去，绝大部分内容会被静默截掉——第三次「跑通但不正确」。

明天要做的叫二次切：标题切完之后，如果块还是太长，就在块内按空行（段落）再攒一刀，攒到接近上限就断开。要想清楚的第一件事是——断开的位置怎么选，才能不把一句话切两半。
