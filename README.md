# rag-lab

**在线看** → <https://hugeaaa-asd.github.io/rag-lab/>　｜　逐题对照「旧：章节路由 vs 新：小节直选」，点开即看，不用装任何东西。

一个**只为搞清楚一件事**而写的 RAG 实验仓库：当检索链路上每一环都可以换参数时，到底哪一环在真正决定效果。

**纯 RAG，不是 Agent 项目。** 单轮「检索 → 拼材料 → 生成」：没有 agent 循环、没有工具调用、没有多轮记忆；链路上只有三处调 LLM（查询改写、小节直选、答案生成），都不带工具。语料是开源书《Hello-Agents》全 16 章（1177 块），书名带 Agent 只因为书本身在讲 Agent。

## 结论

| h3 干净集（20 题，唯一没被调整污染过） | 小节 @1 | 小节 @3 |
|---|---|---|
| 旧：章节路由（79 章里选 3 → 再在章内选小节） | 0.700 | 0.700 |
| **新：小节直选（287 个小节里选 3，章节号由小节号反推）** | **0.950** | **1.000** |

四套 103 题零退化：43 开发集 .925 / h1 留出 .800 / h2 留出 .700 / h3 干净集 .950（均为 @1）。比数字更值钱的是一条教训：

> **分级检索的前提是「上一级不漏」。漏了就是放大器，不是省时间。**

口径是**小节级 Recall@1/@3**——命中的块要落在 `8.3.4` 这一节上，落在 `8.3` 章的别处不算。

## 30 秒核对

```bash
git clone https://github.com/hugeaaa-asd/rag-lab.git && cd rag-lab
python reproduce.py        # 零依赖、约 1 秒、不调 API，复算上面那张表
python build_demo.py       # 生成静态对照页，不加载模型
python api.py              # http://127.0.0.1:8000，带「现场试一句」
```

跑完整问答链路：`pip install -r requirements.txt`，`.env` 里写 `DEEPSEEK_API_KEY`，然后
`python answer.py "智能体怎么像插 USB-C 一样接入外部工具？"`；不配 key 也能 `--dry` 只走检索。
首次运行会从 HuggingFace 拉 `bge-small-zh-v1.5`（向量）和 `bge-reranker-base`（精排），代码里已 `setdefault` 了 `HF_ENDPOINT=https://hf-mirror.com`。

## 链路：七个环节，每环都可以单独换

```
corpus/*.md
   ├─ build_chunks.py   按标题层级切块，代码块按函数边界再切，过滤噪声小节
   ├─ embed.py          bge-small-zh-v1.5，512 维
   ├─ eval.py           向量粗筛 → cross-encoder 精排
   ├─ rewrite.py        口语问题改写成库里的说法，只提名不参与排序  ← 可选
   ├─ route.py          287 个小节一次选 3 个，章节号反推           ← 可选
   ├─ abstain.py        扫描拒答阈值
   └─ answer.py         拼材料 → 宪法提示 → 生成，带 [n] 引用
```

## 每个结论的证据

11 个改动，每个都有对照、都记了耗时。完整的对照表、失败的尝试、被推翻的直觉都在
**[EXPERIMENTS.md](EXPERIMENTS.md)**（约 400 行）。

| # | 改了什么 | 一句话结论 |
|---|---|---|
| ① | 查询改写 | @1 .651→.721、@3 .907→.953，代价 510s→861s |
| ② | 去重放粗筛前还是精排后 | @1 不动，@3 涨 .117，每题慢 5 秒 |
| ③ | 精排时去掉标题 | 掉 4.6 个点——标题是强信号，不能当噪声洗 |
| ④ | 拒答阈值 | 0.05 步长扫全程，最优 0.60，直接写进 `answer.py` |
| ⑤ | 提问风格 | 术语档 top1 全中；极短口语 @1 只有 .231，最短板 |
| ⑥ | 路由加分 bonus | 1.0 给了路由独裁权会翻车，0.5 才保住 @1 收益 |
| ⑦ | 路由准确率 | .923 就是这套链路的天花板，精排再调也超不过 |
| ⑧ | 章节路由 → 小节直选 | @1 .700→.950，本仓库唯一一次结构改动 |
| ⑨ | 放大到 100 万块 | 先崩的是内存不是延迟；同算法 faiss 耗时是 numpy 的 2 倍 |
| ⑩ | 端到端答案正确率 | 检索 .925，答案全中只有 .250 |
| ⑪ | 入口为什么不是聊天框 | 聊天框证明不了「改之前 vs 改之后」 |

## 已知局限

1. **检索指标会高估能力。** 43 开发集小节 @3 = .950，20 题上答案全中只有 .250——差在「同一小节里只捞到其中一块」。
2. **T3 型问题阈值法救不了。** 书里只提过名字的问题 top1 能到 .969，比不少正样本还高，只能靠生成端说不知道。
3. **43 题样本偏小**（分类、对比各 2 题）；同一配置重跑会差一题，1~2 个点的差异一律当噪声。
4. **每题 12~20 秒，离上线很远。** 百万级实测：稳态 2.15 GB、建索引峰值 4.1 GB，延迟 65 ms 反而不是问题。
5. **改写依赖 `rewrites.json` 缓存**，同一个问题第二次问才命中。

完整 7 条（含 h3 特意留的那道错题）见 [EXPERIMENTS.md](EXPERIMENTS.md)。

## 读代码从哪开始

根目录 31 个 `.py` 分三层，读代码只需要第一层 7 个：

| 文件 | 作用 |
|---|---|
| `answer.py` | 端到端入口，带引用标注和引用越界检查 |
| `route.py` | 路由：`route_allsubs` 在 287 个小节里选 3 个；`ROUTE_MODE=sec` 切回旧的两级版本 |
| `rewrite.py` | 查询改写 + 候选扩充 + 本地缓存 |
| `eval.py` | 粗筛 + 精排，43 题基准 `CASES` 也在这里 |
| `llm.py` | 唯一的模型调用层（抽出来是因为 `answer` 和 `rewrite` 互相 import 会死锁） |
| `embed.py` | 向量化，产出 `chunks_vec.npy` |
| `build_chunks.py` | 切块：标题层级 / 段落二次拆 / 代码按函数切 / 噪声过滤 |

另外 24 个是评测与复现（`reproduce.py` 零依赖复算、`eval_*.py` 各口径评测、`api.py` 本地检索服务），25 个是一次性实验（`exp/` 22 + `bench/` 3）。完整清单在 [EXPERIMENTS.md](EXPERIMENTS.md) 末尾的「附录：文件对照」。
