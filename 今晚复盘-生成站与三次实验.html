一、answer.py 的三道闸门

检索、阈值、prompt，三件事管三件事，不能互相顶替。

def answer(question, key=None, dry=False):
    hits = search(question, k=TOP_K)      # ① 检索：找不到就全完
    top = hits[0][1]

    if top < MIN_SCORE:                 # ② 阈值 0.60：不够像就拒答，省一次调用
        return {..., "answer": None, "refused": True}

    prompt = build_prompt(question, hits)
    text, usage = ask_llm(prompt, key)    # ③ prompt 四条铁律：只准用材料、每句标 [n]
    return {...}

三道闸门分工明确，实测各管一段：

题目top1 分结果哪道闸门起作用
USB-C 接外部工具0.985答对，标 [1]① 检索
CrewAI 和 AutoGen 怎么选0.969「材料里没有」③ prompt 兜住 T3
北京好吃的火锅店0.156阈值拒答② 阈值挡 T1
什么是智能体？0.999「材料里没有定义」① 检索喂错料
最值钱的一条

最后那题，模型没说错，材料里真的没有定义。它读到的是 191 字的结尾段，讲神经符号主义。

生成端的诚实，不能证明检索端正确。拒答机制生效了——但它拒掉了一道本该答对的题，这叫假阴性。

二、那道题为什么错

1.1 节被切成 12 块，12 块标题完全一样（## 1.1 什么是智能体？）。我把标题拼进了正文去向量化和精排，于是 cross-encoder 看到问题和标题字面雷同，12 块分数全挤成一团：

idx  len   带标题   不带标题
  1  663   0.998    0.996   << 真定义（是的，结尾段比它低）
 12  191   0.999    0.992   << 实际被选中的那块
 10  698   0.991    0.061
 11  750   0.974    0.020

带标题时最高分和最低分只差 0.025，区分度归零。去掉标题立刻拉到 0.996 vs 0.020。

看起来答案很明确了：别拼标题。然后我跑了全量。

三、两次被数据打脸

第一次：以为标题污染精排

配置@1@3对比基线
基线（带标题 PER=2）0.6510.907—
B 去标题 PER=20.6050.860−5.0 / −4.7 点
C 去标题 PER=30.6050.884−4.6 / −2.3 点

两个方案都低于基线。原因很简单：43 题里有 41 题，标题本身就是答案。问「用状态图编排智能体流程的框架是哪个」，标题就是 ## 6.5 框架四：LangGraph，去掉等于自断一臂。

1.1 那 12 块是特例——它们标题相同，才会饱和。别的节标题各不相同，饱和不会发生。

第二次：以为按 ### 切能救

1.1 节本来有 3 个三级标题（1.1.1 传统视角 / 1.1.2 大模型新范式 / 1.1.3 智能体的类型），但切块只认 ## ，这些边界全丢了。

改了 chunk_by_heading 支持 level=3，块数 1177 → 1305。1.1 节从 12 块变成 13 块——只是多贴了标签，碎还是那么碎。三题验证：1/3 → 1/3，零改善。

根因：语料里 293 个三级子节，86% 超过 800 字。切完照样被 split_long 打碎。而 800 这个上限动不了——bge-small-zh 只吃 512 token ≈ 880 字，再大尾巴就被截断。

两次栽在同一个坑

第一次改「标题怎么拼」，第二次改「按几级标题切」——都在改块，可问题根本不在块上。

单题诊断只能提出假设，全量评估才能验证假设。顺序反了，就白干两轮。

四、真病根：票太少

把失败题的块数拉出来，一眼就看到问题了：

# 节内块数 —— 就是被切碎的程度
## 1.1   12 块
## 8.3   22 块   ← 检索失败
## 4.2   24 块   ← 检索失败

N_SECTIONS    = 15   # 粗筛取 15 个节
PER_SECTION   = 2    # 每节只发 2 张入场券 ⟵ 病根

一个 24 块的节，只给 2 张票。粗筛先筛掉 22 块，剩下的 2 块送去精排，真答案压根没上桌。

1.1 那题之所以选出尾巴块，不是精排眼瞎，是真定义在粗筛那关就被挤掉了。我在精排上折腾了半天，病灶在上一站。

合理的改法是按节的大小发票：

per = max(2, min(8, 块数 // 3))   # 12块→4票，24块→8票，小节能2票

但精排对数会从 30 涨到 70，单题 11.4s → 20s。线上不可能接受，所以这条得和性能优化一起做，不能单干。

五、一个 @3 底下，藏着三种病

今晚最重要的一页。同一个 @3 = 0.907，三种完全不同的病因，药方互不相通：

病症长什么样该动哪里
找对了块，挑错了1.1 尾块 0.999，真定义 0.998配额 / 块粒度
大节进不来8.3 有 22 块，只进 2 块配额策略
根本没找对章节8.3 / 4.2 分数只有 0.79查询改写 / HyDE

第三种是真正的天花板。看这两道题：

用户怎么问书里怎么写top1 分
先检索外部资料再让模型生成答案，这套做法叫什么？## 8.3 检索增强生成（RAG）0.790 → 3.3 缩放法则
一边推理一边调用工具的范式是怎么运作的？## 4.2 ReAct（Reason + Act）0.854 → 4.3 Plan-and-Solve

问题里一个术语都没出现，而文档全靠术语。bi-encoder 建立不了「先检索再生成 ⟷ RAG」这个映射——这套系统骨子里还是关键词检索，问题换个说法就失效。

六、睡前记住这五句

  • 生成端诚实 ≠ 检索端正确。模型说「材料里没有」，可能是你根本没喂给它。
  • 指标不告诉你病因。@3 掉了两个点，可能是三种病里的任何一种，只能逐个看失败题。
  • 单题只能提假设，全量才能验证。今晚两次打脸，都是拿一道题的现象去改全局。
  • 改之前先判断病灶在哪一站。我在精排上折腾两轮，病在粗筛的配额。
  • 术语鸿沟是天花板。向量检索再调，也补不上「口语问法」和「术语标题」之间的裂缝。
